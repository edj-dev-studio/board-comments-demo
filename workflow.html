의사록에서 이사별 정리본까지

지난 의사록을 쌓아 두고, 이사회 전에 안건마다 그 이사가 예전에 한 발언을 모아 정리본을 만든 뒤, 사람이 웹에서 확인·승인하고 이사에게 메일로 보내는 데까지의 흐름입니다.

한눈에 보기

파일 세 개를 넣고, Claude가 두 번 판단하고, 사람이 웹에서 마지막으로 확인합니다. 모든 결과는 SQLite 파일 하나(data/board.db)에 쌓입니다.

사람파일을 만들고, 요청하고, 승인한다 Claude Code판단이 필요한 일 (태그, 관련도, 요약) 프로그램검사·저장·복사·화면 (board)
1 이사 파일 넣기 사람 이름·구분·분야·임기·이메일. 의사록보다 먼저 넣는다 data/directors/
2 의사록 넣기와 태깅 Claude Code 발언마다 질문/의견과 해시태그 0~3개를 붙인다 data/minutes/
3 안건 파일 넣기 사람 다가오는 회의의 일시·회의체·안건명 data/agendas/
4 정리본 만들기 Claude Code 이사마다 안건별로 본인 과거 발언을 골라 직접/애매를 가르고 요약을 쓴다 "11/5 이사회 정리해줘"
5 웹에서 검토·승인 사람 발언을 빼거나 되돌리고, 이메일 초안·PDF를 보고 승인한다 127.0.0.1:8000
6 이사에게 발송 사람 "나에게 발송"으로 모양을 본 뒤, 확인 화면에서 받는 사람·본문을 보고 이사 한 명씩 "보내기" data/mail/ 머리말·꼬리말
data/board.db 이사 · 회의 · 안건 · 발언 · 태그 · 예정 회의 · 정리본이 모두 이 파일 하나에 들어간다. 원본 xlsx는 data/의 하위 폴더에, DB 백업은 data/backup/에 둔다 (모두 git 밖)

누가 무엇을 하나

사람
  • 이사 파일·의사록·안건 파일(xlsx)을 만든다
  • Claude Code에게 "적재해줘", "정리해줘"라고 요청한다
  • 웹에서 발언을 제외·포함한다
  • 승인하거나 승인을 취소한다
Claude Code
  • 이사 발언이 질문인지 의견인지 정한다
  • 발언에 해시태그를 붙인다 (19개 중 0~3개)
  • 안건과 관련된 발언을 골라 직접 애매를 가른다
  • 단락 요약 한두 줄을 쓴다
프로그램
  • 파일을 검사하고, 틀리면 아무것도 바꾸지 않는다
  • 같은 파일을 다시 넣어도 중복되지 않게 한다
  • 정리본에 의사록 문구를 그대로 복사한다
  • 상태(검토 전·승인)를 관리하고 리포트·PDF를 그린다

Claude는 고르기만 하고 문구는 쓰지 않습니다. Claude가 넘기는 것은 발언 번호와 관련도뿐이고, 발언 문구·날짜·실무임원 답변은 프로그램이 DB에서 그대로 복사합니다. 그래서 정리본의 발언은 의사록 원문과 같습니다. 승인도 Claude가 대신하지 않습니다.

정리본의 상태

정리본은 검토 전과 승인 사이를 오가고, 이사에게 보내면 발송이 됩니다. 사람이 승인한 뒤에도 내용이 바뀌면 프로그램이 알아서 검토 전으로 돌려, 승인한 적 없는 내용이 승인 상태로 남지 않게 합니다.

안건 다시 정리, 요약 다시 쓰기, 안건 파일 변경으로 이사가 받을 리포트가 실제로 달라졌을 때. 리포트가 똑같으면 승인이 유지된다.
승인할 수 없는 경우
회의 날짜에 임기가 아닌 이사의 정리본. 화면에 경고가 나오고 승인 버튼이 없다. 그런 정리본은 delete-briefing으로 지운다.
보낼 수 없는 경우
승인되지 않은 정리본, 보내기 직전에 회의 날짜 임기가 아닌 이사, .env나 머리말·꼬리말 파일이 없거나 빈 경우. "나에게 발송"은 상태·임기와 상관없이 되고 상태를 바꾸지 않는다. 보내다 실패하면 상태는 그대로이고 발송 이력에 실패 이유가 남는다.

안건이 바뀌었다안건 파일을 고쳐 다시 적재빠진 안건 단락은 지워지고, 새 안건은 다음 정리 때 채운다. 리포트가 바뀐 승인 정리본은 검토 전으로
회의 일정이 바뀌었다delete-agendas로 옛 회의 삭제 후 새 파일 적재옛 회의의 정리본도 함께 지워진다 (되돌릴 수 없어 확인 후 실행)

한 안건만 다시 정리하고 싶다"○○ 안건 다시 정리해줘"그 안건 단락만 새로 만든다. 그 단락의 제외 표시는 사라진다
요약만 고치고 싶다"요약 다시 써줘"발언과 제외 표시는 그대로, 요약만 바뀐다
메일 머리말·꼬리말을 바꾸고 싶다data/mail/header.txt·footer.txt를 메모장으로 고쳐 저장다음 화면·발송부터 바로 쓰인다. 확인 화면을 연 뒤에 고쳤으면 "보내기"가 거부되므로 확인 화면을 다시 연다
승인 뒤 이사 이메일이 바뀌었다이사 파일을 고쳐 다시 적재발송·다시 발송은 그 순간 DB의 이메일로 간다. 확인 화면에서 받는 주소를 보여 준다
